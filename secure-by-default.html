Custom rules we turn on so you don’t have to

Beyond the platform defaults, we apply a focused set of security, rate-limit, and response rules on Cloudflare. They block common probes, slow down abuse, and stop sensitive paths from ever serving a successful page.

Block AI crawlers that ignore robots

Requests from known AI search bots are blocked when they hit anything other than robots.txt — so training crawlers don’t scrape your content by default.

Action: Block

Close off sensitive files and common exploits

Paths like .env, .git, config files, phpinfo, adminer, AWS credential folders, backups, and server-status return nothing useful. Scanners looking for exposed secrets are stopped at the edge.

Action: Block

Protect login and admin surfaces

XML-RPC and WordPress-style login or admin URLs are challenged or blocked (while still allowing legitimate AJAX endpoints). Brute-force and automated login attempts are cut off early.

Action: Managed challenge or block

Stop empty and tool-based user agents

Empty user agents and well-known scanning tools (sqlmap, nikto, nmap, masscan, gobuster, and similar) are blocked. Scripted probes never reach your origin.

Action: Block

Challenge high-risk networks and regions

Traffic from selected high-risk hosting ASNs and certain high-abuse countries is challenged before it can interact with the site. Legitimate visitors pass; noisy sources are filtered.

Action: Managed challenge

Rate limits that stop floods and login abuse

General request volume is capped (for example 60 requests per 10 seconds). Login and XML-RPC style paths can be limited even tighter so credential stuffing dies quickly.

Action: Block for a short window

Block successful hits on admin and sensitive pages

If a request somehow reaches an admin, login, XML-RPC, or secret file path and would return a normal HTML page, the response is blocked. A “200 OK” on those paths never leaves the edge.

Action: Block (response rule)

Never serve successful sensitive files

Even if a sensitive file were somehow present, a successful (200) response for .env, .git, config, phpinfo, or backup paths is blocked. Accidental exposure is treated as a hard fail.

Action: Block (response rule)
